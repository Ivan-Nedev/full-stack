- **Етапи в изпълнението в JVM**
    
    - **Class Loader** – зарежда `.class` файловете в паметта
        
    - **Bytecode Verifier** – проверява сигурността (да няма невалидни инструкции)
        
    - **Interpreter** – изпълнява bytecode ред по ред
        
    - **JIT Compiler** – превежда често използвани методи към машинен код
        
    - **Garbage Collector (GC)** – автоматично освобождава неизползваната памет
        
- **Паметта в JVM**
    
    - **Heap** → за обекти и инстанции
        
    - **Stack** → за методи, параметри, локални променливи
        
    - **Method Area (или Metaspace)** → за класове, константи, статични променливи
        
    - **PC Register** → адрес на текущата инструкция
        
    - **Native Method Stack** → за методи, написани на други езици (напр. C)
        
- **JIT оптимизация**
    
    - Компилира “горещи” (често извиквани) методи в машинен код
        
    - Поддържа _adaptive optimization_ – колкото повече работи програмата, толкова по-бърза става




1️⃣  Пишеш код → .java файл
     ↓
2️⃣  Компилаторът (javac)
     - Проверява синтаксиса и типовете
     - Превежда Java кода в bytecode → създава .class файл
     ↓
3️⃣  Стартираш програмата (java Main)
     ↓
4️⃣  JVM стартира → активира JRE
     ↓
5️⃣  Class Loader
     - Зарежда нужните .class файлове в паметта
     - Свързва ги със стандартните библиотеки (rt.jar, .jar файлове)
     ↓
6️⃣  Bytecode Verifier
     - Проверява дали bytecode-ът е безопасен
       (без невалидни операции, достъп до памет и т.н.)
     ↓
7️⃣  Execution Engine (Сърцето на JVM)
     ├─ Interpreter: изпълнява bytecode ред по ред
     ├─ JIT Compiler: превежда често използвани методи в машинен код
     └─ Code Cache: пази компилирания код за повторна употреба
     ↓
8️⃣  Runtime Data Areas (памет)
     ├─ Heap → обекти и инстанции
     ├─ Stack → методи, параметри, локални променливи
     ├─ Method Area → класове, статични променливи, константи
     ├─ PC Register → коя инструкция се изпълнява
     └─ Native Method Stack → за външни методи (C/C++)
     ↓
9️⃣  Garbage Collector (GC)
     - Следи за неизползвани обекти в Heap-а
     - Автоматично освобождава паметта
     ↓
🔟  Машинният код (чрез JIT) → процесорът го изпълнява директно
     ↓
✅  Програмата приключва → JVM освобождава паметта
